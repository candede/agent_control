## Delivered Contracts

- **Provider request:** Exact `POST https://graph.microsoft.com/v1.0/security/runHuntingQuery` with delegated/application `ThreatHunting.Read.All`, code-owned KQL, bounded `Timespan`, no `workspaceId`, three safe attempts, a 30-second logical budget, 2 MB response cap, and a 201-row truncation sentinel retaining at most 200 rows.
- **Projection v3:** `agents_inventory`, `agent_activity`, and `agent_tools` are the only templates. Shape-aware KQL computes value-free `ProjectionValid`, applies exact predicates before invalid values are nulled, and projects only named fields. A malformed selected row therefore reaches the adapter's false-signal rejection instead of disappearing as `no_data`. The adapter requires the exact schema and strict strings; the repository independently rejects arrays/objects in every scalar slot, including known allowlisted fields. Original dynamic structures, `RawEventData`, provider bodies, unknown fields, content, prompts, instructions, memory, and tool arguments/results are never persisted.
- **Microsoft semantic compilation:** `@kusto/language-service@0.0.297` was acquired and inspected from the approved feed inside Docker, but its published legacy API exposes only query prettification and IntelliSense context, not semantic diagnostics or result types. The official Microsoft successor `@kusto/language-service-next@12.4.1` is therefore pinned as a backend dev dependency and loaded through a small CommonJS Bridge helper. It parses and semantically analyzes all three actual generated templates against independent native table declarations, returning zero diagnostics and the exact expected string projection names, order, and types. The compiler is absent from the production `/release` tree.
- **Inventory limitations:** Exact IDs, bounded scalar metadata, dates/counts, and explicit `not_supplied`/`empty`/`present_unqualified_shape`/`not_exposed` states are retained. Published `AgentsInfo` documentation does not qualify nested owner identity, permission risk, or authentication layout, so those details remain count/state-only and risk remains `not_exposed`.
- **Activity limitations:** IA/CH/ET fields are selected from their documented direct/Event/CopilotEventData locations. No documented CloudAppEvents mapping was found for model/provider names or token counts, so those fields are absent rather than inferred. Optional dates are exact millisecond UTC strings. `rootSpanObserved` reports only a validated root `invoke_agent` span; it does not claim downstream admin-center ingestion, complete trace collection, or conversation availability. The former admin-center establishment boolean was removed from the current contract; immutable migration 19 alone still converts that historical v2 JSON.
- **Provider authorization:** Every new send requires a current exact query-version-3 provider qualification keyed by tenant, authorizing principal, result scope, token mode, template, non-time target hash, permission revision, contract revision, and configuration revision. It expires after 24 hours. Expiry denies before token acquisition; a sibling or newer unrelated approval cannot authorize a request.
- **Saved-data authorization:** The same explicit Administrator plus SecurityReader approval creates a separate exact retained-scope row bound to the successful qualification job. It expires after 30 days and is attached by ID to every ordinary job. A current SecurityReader can read only bound history, counts, rows, and CSV while that approval remains unexpired and nonrevoked, even when the 24-hour provider proof expires or the provider is unavailable.
- **Revocation and sharing:** Exact revoke requires Administrator plus SecurityReader, is CSRF protected, audits only safe metadata, and immediately hides every bound saved result without deleting rows. Delegated results remain principal-private. Application results can be read by another current SecurityReader only under the exact enabled application identity/shared scope/configuration revision and retained approval. Configuration or retained-scope revocation hides them immediately.
- **Offline trust boundary:** Local roles, retained revocation, and application configuration are enforced on every saved read. Agent Control cannot discover an external Defender RBAC/data-source assignment revocation while offline, and the UI/runbook no longer represent retained authorization as current provider visibility proof.
- **Durability:** Jobs retain the 15-minute deadline, four-activation and 12-request limits, execution fencing, explicit resume, prior-success linkage, observed/unobserved ranges, 30-day result retention, and source-safe CSV. Startup/navigation make zero provider requests.
- **UI/API:** Catalogs expose provider qualifications and retained scopes separately. The hunting view shows separate clocks/notices and an exact role-gated revoke command. HTTP outage/Retain/revocation/application-sharing behavior uses the packaged Express policy and repository, not state-only spies.
- **Validation harness:** Isolated database cleanup now waits for both pools to settle and retries an ordinary guarded drop before surfacing a failure, avoiding false `57P01` errors from an immediate force-drop while PostgreSQL backends are still detaching.

Migration 21 adds the exact retained-scope table, active/visibility indexes, query-version-3 constraints, and the non-null ordinary-job binding. It was applied through the checked-in deployment path and is now immutable. Migrations 1 through 20 were not edited. New schema work starts at migration 22.
