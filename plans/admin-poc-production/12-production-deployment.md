# Phase 12 - Production Deployment

## Mission

Deliver `deploy-azure.ps1`: a wizard that deploys the tested combined Express/React artifact to one Linux App Service on one App Service Plan, with a separate Azure Database for PostgreSQL Flexible Server and an administrator-prepared existing Key Vault supplied by resource ID. Both application hosting and database are PaaS; Microsoft manages their underlying hosts, not the customer. Use an approved budget/maintenance window, preserve committed data across restarts/redeployments and verify actual healthy hosted POC behavior. No customer-managed VM, database container, Azure Files/NFS or Cosmos implementation.

## Prerequisites

- Follow the README's fresh-session contract. Read Phase 11's completion/linked issues, Phase 10 integrated package proof, Phase 01 Docker/export/local script/bootstrap/importer contract and Phase 02 Entra manifest/auth/deployment setup guide.
- Required implementation and reproducible core repairs are complete; actual local/security/browser/restore/capacity evidence and runbooks exist. External evidence can remain unavailable with containment, never relabeled passed.
- Obtain operator approval for exact production target and changes before writes. The administrator prepares the existing vault and its six named values before the wizard; secrets are never wizard/chat inputs or tracked files. A logged-in Azure account or supplied vault ID is not approval/access proof.
