# Agent Control

## Quick Brief

This React client is built into the combined Agent Control Express artifact. The supported local workflow is the repository-root Docker deployment; there is no separate production frontend origin or host Node/Vite requirement.

## What This App Does

Agent Control presents saved, explicitly refreshed Microsoft Graph package observations and saved Power Platform inventory. Package list/detail reads use least-privileged delegated or separately approved application read access. Provider actions are capability-gated and never run on navigation.

Admins can use the app to:

- Sign in with a work or school account through Microsoft Entra ID.
- View authorized saved Copilot package observations.
- Search and filter agents by name, description, publisher, host, ID, or blocked state.
- Block or unblock a single Copilot agent.
- Select multiple agents and run bulk block or unblock actions.
- Inspect Available to and Installed for assignments when authorized.
- See package access controls disabled with the missing conditional-write protection explained.
- See owner reassignment disabled with its missing owner-readback/conditional-write contract and Microsoft documentation link.
- Review bulk action results, including succeeded, skipped, and failed packages.

The browser does not call Microsoft Graph directly. It calls the local Express backend, and the backend calls Microsoft Graph on behalf of the signed-in user.

## Requirements

Use the host and identity prerequisites in the [quick start](../README.md#quick-start): PowerShell 7, Docker with Compose v2, a browser, and an approved single-tenant Entra application's tenant ID, client ID and client secret for initial onboarding. An administrator must add the [required API permissions and grant admin consent](../docs/deployment-setup.md#api-permissions-administrator-prerequisite) before feature use. The app does not request feature grants. Microsoft Agent 365 licensing applies to package APIs.

## Run Locally

From the repository root:

```powershell
pwsh ./deploy-local.ps1 start
# Omitting start is equivalent:
pwsh ./deploy-local.ps1
```

The first or incomplete start prompts for tenant ID, client ID, hidden client secret and port (default `3001`). State is fixed at repository-root `.local/<lowercase-project>/`; there is no custom location. Use `pwsh ./deploy-local.ps1 start -Project newCustomer` to onboard or reuse `.local/newcustomer/`. Later starts reuse all saved values, including the port, without prompting. Open `http://localhost:<saved-port>` (default `http://localhost:3001`). Every `start` builds images, migrates, tests and starts the app. Build, test, lint, browser automation, Node and npm all run in Docker. The JSDOM suite uses at most two workers so the complete operator gate does not starve time-bound UI tests on shared machines; test assertions and deadlines remain unchanged.

The only public commands are positional `start` (default), `stop` and `edit-config`, plus `-Project` (default `agent-control`). `stop` preserves data and secrets. `edit-config` prompts for all four settings; Enter keeps each current value, and the current secret is never displayed. Unchanged settings are not rewritten and leave a running app untouched. Accepted client ID, client-secret or port changes safely stop the app and leave it stopped until an explicit `start`. A changed port requires the matching Entra Web callback `http://localhost:<saved-port>/api/auth/callback`. Input validation does not validate live credentials.

The tenant ID can change before a database volume exists, and a previously missing tenant ID can be filled in. Changing a nonempty saved tenant ID on an existing volume is rejected before stopping the app or writing settings. Edits do not migrate data between tenants; use a separate project for another tenant. See the [deployment setup](../docs/deployment-setup.md#local-workflow) and [operator-only maintenance helpers](../docs/operations.md#operator-only-local-helpers) for recovery and isolated database tests.

Changing the saved client/application ID on an existing volume records `control/reauthenticate` while the app is stopped. The next `start` clears only persisted login sessions before reopening, requiring sign-in under the new app registration. The session-signing secret and all business data are preserved. Secret-only and port-only edits do not schedule this purge.

## How To Use The App

1. Open `http://localhost:<saved-port>` (default `http://localhost:3001`) and sign in when identity is configured.
2. Review **Permissions > App prerequisites**; an administrator configures any missing grants in the existing app registration, then you sign in again.
3. Explicitly refresh package observations; navigation itself never calls Microsoft Graph.
4. Search/filter saved rows and inspect package source, freshness, deployment, block state and assignments according to the current app role.
5. For block/unblock, review the exact targets and risk preview, confirm the change, then monitor the durable job and provider verification. No prior canary is required; current provider authorization remains enforced.
6. Reconcile an inconclusive item by read only; a new write always requires a new preview and confirmation.
7. Sign out when finished.

The sign-in form checks the backend's 254-character username limit and organization-domain syntax, including internationalized domains, before submitting. The backend still owns tenant routing and authorization. A failed or malformed sign-in configuration-status read does not prevent checking an existing session; signed-out users see a warning and can still try manual sign-in. Sign-out retries clear the previous error, and late logout responses cannot add errors to a session that has already been cleared.

Leaving the sign-in page cancels its pending request, including when browser history caching preserves the mounted form. Returning through a cached Back/Forward entry rechecks the session through the existing single-flight revalidation path and retires previous-session data before showing the workbench. Departure also cancels a pending logout and releases its local lock; restoration checks the actual session without waiting for or replaying that abandoned command. It does not reload the page or automatically restart Microsoft sign-in. Abandoned success/error responses cannot redirect, remember an old username, or change a newer attempt; ordinary page display does not duplicate the session check.

### Inventory workspace

After sign-in, the workspace checks saved sync status without assuming first-time setup. Agents, Users, and Audit show layout-matched loading skeletons while that status is unknown and until the destination's initial data read completes. Skeleton placeholders are non-interactive and hidden from assistive technology; the loading status sits outside the busy region so its announcement is not deferred until that region disappears. The app bar stays available, and Sync and Permissions remain accessible. Only a confirmed incomplete setup opens the first-sync dialog or shows the **Setup needed** hint. An initial status-check failure instead shows an inline error with retry and recovery navigation. No artificial loading delay is added; later refreshes retain each page's existing loading behavior.

Skeletons contain decorative table overflow on narrow screens and stay static when reduced motion is requested. Forced-color palettes retain system-color outlines around placeholders, including pending metric counts, so unfinished reads do not appear as blank content. Service-free `browser/appStyles.spec.ts` checks cover these styles without starting the application.

Synthetic layout inventory/package pages honor limits and cursors while preserving their captured selection. Service-free geometry checks reject overlapping recovery controls and clipped diagnostics; style checks exercise dynamic facet loading, failure, retry, empty and retained-option markup without replacing the focused search. Component unit tests, rather than static markup checks, verify request cancellation and account ownership.

An independently cancelled Agents transport ends the initial skeleton and exposes **Reload saved agent inventory**, rather than leaving a loading or empty-success surface. Cancellation during replacement loading likewise shows the saved-read failure and disables export until recovery. Retry reads saved data without starting provider collection; requests abandoned by navigation, supersession or account changes remain silent.

The Agents page gives the table priority: a compact app bar replaces the large masthead, source tabs sit beside the title, and inventory/report counts share one summary strip. The neutral background, sans-serif typography, and indigo accents distinguish navigation and selected states without competing with the data. Permissions has a single navigation entry with an issue badge; sign-out remains available in the app bar.

Search, **Show agents**, **Filters**, and **Columns** share the table toolbar. Filters opens a keyboard-accessible panel for platform, assignment, host, publisher, package status, creation age, environment, and sort order. Changes apply immediately. Close or Escape returns focus to Filters; outside interaction also dismisses the panel. Active filters remain visible as removable chips, including after following a bookmark or browser history. Clear/Reset filters preserve sorting, and table headings still sort directly.

Column choices are local browser preferences scoped to the account and tenant; changing them does not reload inventory or change sorting. Changing accounts or tenants closes the column picker and clears its search; same-account inventory updates preserve the picker and column choices. Storage failures remain visible without blocking page-local choices. Projected usage columns follow the same report-identity and availability checks as other usage values. Environment filter labels belong to the current saved selection and account, match environment IDs case-insensitively, and fall back to the exact ID while a replacement label is unavailable.

Row-level package actions require a complete single-version record; a bounded primary-package preview does not qualify. Multi-version groups still support whole-group selection and exact-version management through details. If adding a quarantine target is refused because of the selection limit or a different saved snapshot, the checkbox preserves its existing mixed selection state.

Verified package mutations retire the affected saved status/access columns in both rows and open details. Complete records recompute those summaries from their updated versions; bounded groups show Unknown for the affected summaries until a successful saved-inventory reload, because their previews cannot establish whole-group state or exclude changed off-preview versions. Unrelated columns and selections remain intact. A failed reload does not revive stale summaries or start package-detail reads against the previous selection; saved-version selection and detail retry wait for explicit saved-inventory recovery without displaying a false loading state.

Facet options also belong to the account scope: changing accounts cancels pending option reads and withdraws the previous account's options, even if the selection ID is unchanged. Late facet invalidations and environment-label errors from a replaced selection cannot cancel or add page errors to its replacement inventory read. Local filter validation errors remain visible while replacement inventory is loading. Invalidation of the current selection still withdraws its rows and counts and requires reloading saved inventory.

Facet selection changes restart option paging; account changes also clear option searches. Revisiting an earlier selection or search cannot revive its retired options, errors or environment label while a new read is pending. A focused option-search input remains available through loading, empty results and errors until the filter panel closes. Pending environment-filter edits do not repeat the captured selection's label request. Creation age accepts only whole days from 1 to 3650 (or an empty value for any age); valid numeric spellings are normalized to decimal whole days so bookmarks retain the same restriction without redundant inventory reads. Invalid edits leave the applied filter unchanged and show an error. Reset focuses the first enabled filter, including when saved facet choices are unavailable.

Facet searches accept at most 256 characters, matching the saved-read API limit. Whitespace-only option searches act as an empty search without reloading or resetting the current unfiltered page; spaces in nonblank searches remain literal. **Retry options** retries only the failed option page, clears its error while loading, and returns keyboard focus to the existing select.

Inventory scope and reporting scope remain separate: source tabs select the inventory, while **Report context** selects the shared usage report for Admins. The first two counts open their unfiltered inventory lists; reported counts are independent and are never added to inventory totals. Unknown and partial coverage remain explicit. Export and saved-source freshness stay next to the page title.

Report-summary refreshes wait for replacement inventory to identify the exact selected report, cancelling obsolete reads rather than briefly loading the previous set. Inventory-only filter and page changes reuse the summary. Inventory with no selected report does not request a latest-report fallback. The summary distinguishes waiting for inventory, loading report evidence, failed evidence (with local retry), and no selected report; unavailable evidence never enables the reported-used shortcut or appears as zero.

In the agent modal's **Manage** tab, the selected version's **Package ID** is displayed inline beneath its version and publisher, without an expandable disclosure.

Saved-inventory verification resets pagination before admitting a new selection, avoiding an immediately cancelled duplicate capture. Switching between Agents, Sync and local Audit shares an identical pending verification instead of cancelling and recapturing it. Session, query, scope and revision changes still retire obsolete reads, as does leaving all inventory-consuming views; late completions cannot restore their receipts or errors. Power Platform job history is refreshed on workspace/session or data-revision changes, not on every inventory filter, sort, or page change. A completed bookmarked package-refresh job invalidates saved inventory only once per session, and its error is cleared when that bookmark is left.

Refresh-target pages belong to the session, authorization mode, job and exact result revision. Changing any of them resets paging and cancels abandoned reads; equivalent status renders and revisited pages reuse the same revision's saved results. Concurrent readers share transport ownership, and saved-query invalidation revalidates active pages. Pending reads withdraw old rows and errors. **Retry targets** retries only the failed page; **First targets** can recover from a rejected cursor. A changed revision instead requires **Refresh status**, which rereads the bookmarked job without submitting provider work or invalidating the same publication again. Status-read failures remain retryable and identify any retained progress as last observed.

Off-page agent bookmarks show detail loading until the exact saved read finishes or is cancelled. Retired package-refresh and access-preview requests abort their browser transports so late authorization failures cannot clear a newer screen's session. Aborting a browser request does not cancel a durable provider job already accepted by the server.

Package mutation admission and job commands, Power Platform refresh commands, and quarantine commands also cancel their browser transports when their owning scope is retired. Closing an exact source-job or quarantine view cancels its pending request; an abandoned authorization failure cannot revalidate the replacement view. The workspace-owned Power Platform refresh still survives tab navigation and keeps its loading state until admission finishes, without submitting duplicate work.

Sync refresh commands reject overlapping same-batch submissions before React updates their disabled controls. An open Power Platform source job owns its commands and status polling; the diagnostics controls cannot compete with it, and an already-pending workspace command must settle before the inspector admits work. Status transitions refresh history, but failure, cancellation, and authorization waits do not reload unchanged inventory. A successful observed publication invalidates saved inventory once per job and session. Power Platform exports require a settled, valid inventory selection: pending or failed verification, including a queued same-batch reload, cannot export the previous snapshot.

Exact source-job commands cancel any pending status read and show the retained progress as last observed while updating. Resume/cancel responses are used directly: only a running result schedules another read after the polling delay; a terminal result does not reread or republish itself. Starting a new refresh hands its already-observed response to the new exact inspector without an immediate duplicate read or publication; only a running result starts delayed polling. This handoff is discarded on close, navigation, or session change, so later bookmarks read current status. Reauthorization returns to the exact source bookmark and still requires explicit resume. Initial loading and command waits expose their busy state to assistive technology. Opening an already-succeeded source bookmark also invalidates saved inventory once per session, even when a different job is latest; reopening it does not invalidate that publication again. Source-job bookmark UUIDs are case-insensitive and normalized to the server's lowercase IDs so the inspector and background poller retain one owner.

Returning to Sync also reconciles publications first discovered through refresh history, including a newer completed job, instead of retaining the previous cached inventory. Delayed history cannot replace a newer command or exact-job observation. First-inventory `preparing` and `not_collected` messages appear in both health and diagnostics, without implying a verified receipt or enabling matching-detail refresh. Refresh-command and history failures remain visible inside the diagnostics dialog; failed history labels retained job status as last observed. An admitted Power Platform export closes diagnostics so its progress, cancellation, retry and download controls are accessible on Sync; a rejected admission leaves diagnostics open.

Workbench history entries bind private detail, selection, report and job links to their account and session. Session revalidation retires older entries' private state while keeping public filters; a same-account document reload can retain its current bookmark, but a replacement account cannot inherit it. Fresh, unowned deep links still resolve under the current account's server authorization. Agent page numbers do not select another page's cursor: when history requests a different numeric page without an owned stored selection, navigation returns to the first page of the saved selection.

Routing rejects repeated scalar query parameters instead of choosing an arbitrary filter, detail or job; only `selected` and `selectedResource` are multi-value fields. Invalid explicit filters cannot revive legacy aliases. Environment IDs and creation-age spellings are normalized before inventory reads, preserving the same selection for equivalent bookmarks. Serializers omit malformed numeric state and control-character searches rather than advertising unsupported requests.

The source-member diagnostic component uses the same shared saved-membership read as published-version paging. Concurrent member, section, and row readers share their requests; retiring one reader cancels the transport only when no readers remain. Saved-query invalidation revalidates the active page, while equivalent renders, focus, and reconnect do not reload it. Account, tenant, role, selection, and record changes retire the entire member view, including its selected member: returning to an earlier owner cannot revive its rows or selection.

Source-member, section, and row failures stop their loading indicators and offer explicit retries of only the failed page. Paging controls retain focus through pending and failed reads, and **First members**, **First detail sections**, or **First detail rows** can recover from an invalid cursor. Pending retries share one request and withdraw the previous error; empty states describe the current saved page, not the whole inventory. Changing section pages withdraws the old sections and rows and cancels pending child reads before requesting rows from the replacement section page. Selection invalidation at any level withdraws all member rows and inspection actions, notifies the owning view through `onInvalidated`, and requires a replacement saved selection rather than retrying the rejected one.

Unified-agent tables wrap long names and identifiers within their configured scroll surface. Detail dialogs keep their content and recovery controls reachable with long titles/errors, short viewports, or enlarged text; tabs and management headings wrap rather than clipping controls. Disabled published-version/section selectors and unavailable member-paging directions look unavailable without hiding focus or dimming still-usable actions merely because their region is busy. These layout states do not initiate reads, alter cache ownership, or remount controls.

Published-version and saved-configuration paging restarts at the first page when the account, tenant, roles, saved selection, agent, or pinned source changes. Source-member navigation and selected child rows also belong to that principal and selection. Obsolete reads are cancelled; equivalent props, focus, and reconnect do not reload settled pages. Concurrent version/configuration readers share their active request without cancelling each other. Failed version/configuration reads offer a single in-flight explicit retry with loading feedback. If the selection has expired or been invalidated, its options/details are withdrawn: reload saved inventory explicitly to obtain a new selection, rather than retrying the rejected selection or refreshing providers.

Published-version pagination keeps its focused controls mounted through pending and failed page reads. A failed later page can be retried or left with **Previous versions**, without bypassing selection invalidation. Unavailable paging directions remain focusable but do not start requests. An empty or native-only membership page is identified as having no published versions on that page, not as proof that the agent has no other versions. Membership retries also respect the parent dialog's disabled state.

Later published-version or source-member readers reuse an already-observed immutable membership page without another request. Explicit cache invalidation still revalidates valid pages, but cannot restart a membership selection already rejected by the server.

Saved channel, connector, and operation pages likewise keep paging controls mounted through loading and ordinary failures, with **Previous** available to leave a rejected cursor. Revalidating configuration withdraws old rows and counts and cancels abandoned nested operation reads. Explicit retries show loading instead of the previous error and share their pending request; invalidated selections still require reloading saved inventory.

Configuration paging and retries check the current cache before admitting a queued click, so they cannot supersede revalidation or follow a replaced cursor. Later readers reuse an already-observed selection's settled configuration without reloading it or cancelling its operations; abandoned pages are not retained. Explicit cache invalidation still revalidates active reads. A rejected configuration selection instead retires its cached parent and sibling reads, aborts their pending requests, and cannot be revived by another observer or cache invalidation. Standalone connector panels share this ownership with their operation reads too.

In the workbench, an invalidated bookmarked logical detail, selected-version detail, version-membership, channel, connector, or operation read retires the owning inventory selection: the detail modal closes, sibling reads are cancelled, and old rows and export actions are withdrawn until an explicit saved-inventory reload. This also applies when a bookmarked package read fails before its modal opens. Reloading clears the retired detail error without replaying that bookmark or refreshing providers. Late invalidations from a replaced selection or version cannot retire its replacement or discard an outstanding bookmark that the replacement inventory will resolve. Ordinary child-read failures remain local and retryable.

Switching published versions preserves the same native agent's configuration pages and pending reads; it does not reload channels or connectors. Inline connector paging resets with its saved selection or source snapshot. Paged configuration preserves the provider's partial/truncated evidence: zero retained details do not imply that no connectors or operations exist. Environment and configuration expiry notices update at their own deadlines and on browser return, without refreshing providers or reloading saved data.

### Users workspace

The Users page reuses the Agents summary-strip and table styles. The four paid-user adoption cards and **Report context** occupy one connected row on wide screens; the cards wrap into two columns and the report selector moves below them on small screens. Cards remain direct cohort filters. Both paid and non-paid user lists place search, matching counts, **Filters**, CSV export, sortable headings, rows and pagination inside one table surface. User names open the existing details dialog, and source coverage remains collapsed below the table. Paid and non-paid cohort filtering, report selection and exports are unchanged.

Routine source refreshes do not add progress banners to saved Users views. Settled notices reflect saved-source availability: a running attempt does not make unavailable license data or stale Office app activity current. Existing freshness notices are withheld while the page read is pending and are updated when it settles.

Reported-user page-local filters reset when the tenant, principal or effective roles change. A source-data revision preserves those filters but retires open details, pending revalidation and exports before loading replacement evidence. Search replacement cancels obsolete reads and withdraws their rows and export actions; late results or selection errors cannot replace the current search or its loading state.

The **User cohort** selector contains only paid M365 Copilot users and active users without paid Copilot. Agent ownership, creation and last-modifier relationships are consolidated in the user modal's **Responsibility** tab, with an agent count, relationship badges, source dates and links back to exact agents. Partial inventory coverage does not add a warning banner or manual-refresh prompt; failed reads and unavailable responsibility data remain explicit. Agent **Owner**, **Created by** and **Last modified by** links open `/users?detail=<object-id>&tab=responsibility`, including people outside both cohorts. Missing directory, license or usage evidence stays explicitly unavailable. Old responsibility-cohort person bookmarks open this same modal; the standalone people list is removed.

User-detail tabs retain their visited panels and pending reads across both tab clicks and browser-history tab changes. Changing the exact user, selection or account clears private relationship filters, visited-panel state and fallback identity labels. Closing the final observer cancels its saved reads; reopening does not reuse abandoned evidence. Source revisions still withdraw obsolete profile/license evidence, while inventory-only revisions revalidate responsibility independently.

Cancelled user, linked-directory, paid-feature and reported-agent reads stop showing loading and offer local retry. Cancelled cache revalidation cannot revive evidence marked for reload, and focus does not replay that incomplete read. Explicit retries share the pending request. A peer's report restart still preserves another reader's valid immutable selection, but does not exempt it from later cache invalidation or cancelled revalidation. Rejected or expired exact selections require explicit restart, cannot be replayed by cache invalidation, and cancel pending pinned detail reads; cancelling a direct-user restart cannot restore the rejected child evidence. Earlier read failures do not obscure expiry, and retries recheck known pinned deadlines before sending a request. Retrying a rejected cursor returns to the first page without losing that selection's original deadline; expiry still cancels a stalled retry and offers the appropriate selection recovery.

Responsibility source health comes from the API's `sources` metadata, not the presence of every relationship role. The redundant `coverage` and `unknownAgentCount` fields and their all-three-roles calculation are removed without compatibility aliases. Reported role lists and `invalidReferenceCount` remain independent of collection health; the modal uses the selected person's explicit state for unavailable data.

Filters focuses the first enabled field even when organization options are loading or unavailable. Company and department option searches restart from the first page when the search or selection changes; once focused, each option-search input stays visible until the panel closes so clearing it does not interrupt keyboard input.

Unresolved report identities load only after explicitly expanding their list in **Data sources and coverage**. Closing coverage or withdrawing/replacing its selected evidence closes the list and cancels pending child reads. Reopening coverage does not silently reload identities.

If CSV export admission, processing or download verification invalidates a paid-user selection, the page withdraws its rows and counts, closes details and unresolved identities, and offers **Restart selection**. Restart preserves the current filters while loading a new selection; export stays disabled until it loads. Other export failures leave the displayed selection intact.

Paid-user, reported-user and agent-report export invalidation also retires the rejected selection in the shared page cache. Mounted peers withdraw that same evidence, pending reads are cancelled, and a view revisit cannot revive its cached rows. Newer selections remain usable. Restart is explicit in the rejected view; ordinary focus events do not retry it or recreate the export.

## Notes

- **Audit is local-only:** it records actions performed through this app, including blocking/unblocking and evidence exports. Provider investigations start in individual details: **Agents > agent details > Activity > Purview audit** searches saved exact bot/environment records, while **Users > user details > Purview audit** runs explicit searches with a fixed verified user identity and server-scoped history. Paid and reported-user modals support the latter only with a current directory link. Opening a modal or search panel never starts a live search. Legacy provider Audit URLs normalize to local audit.
- **Permissions > Log setup** keeps Microsoft 365 connector, Copilot Studio runtime-protection integration and Purview auditing checks in one place. Each check has a portal link and expandable steps, admin roles and API permissions. These are manual checks, not detected connection states; token readiness does not verify them. Agent Activity keeps a short identity blocker, a Setup & permissions action, and collapsed technical/saved-observation details. Connector setup does not repair missing app identity mappings or collect saved Purview records.
- **Resolve log identity** explicitly verifies newer Studio Entra Agent IDs through Microsoft Graph. Delegated `AgentIdentity.Read.All` and tenant admin consent are app-registration prerequisites, not an in-app authorization option. The server verifies the saved source candidate and retains scoped evidence; the browser sends only the selected saved agent reference. A successful lookup refreshes saved context before enabling Defender inventory/runtime searches. Switching agents, principals or roles cancels pending work, and no hunt starts automatically. Saved authorization, not-found, provider-error and expired outcomes remain visible without retrying Microsoft. Unsupported Agent Builder crosswalks and missing Purview bot/environment associations remain distinct from portal configuration.
- **Purview auditing status:** Open Audit Search is a search-page handoff, not a settings/status page. Its recording banner can enable auditing, but an absent banner or empty search history is not a status result. Expanded setup provides `Connect-ExchangeOnline` and `Get-AdminAuditLogConfig | Format-List UnifiedAuditLogIngestionEnabled`: True means enabled, False means disabled, and an error means unknown. Use Exchange Online PowerShell, not Security & Compliance PowerShell. The separate enable command requires the Exchange Online Audit Logs role; allow up to 60 minutes and recheck.
- JSON API calls and CSV downloads expose typed cancellation and network failures, including failures while reading response bodies. Invalid successful JSON is an explicit response error; malformed HTTP problem bodies retain the response status and request-ID header without trusting incorrectly typed fields. Provider consent failures remain distinct from session expiry. Package-refresh responses include the backend's terminal Cancelled state.
- A rejected session CSRF token withdraws cached private data and revalidates the account, including after signing in in another tab. The rejected write is not replayed, and late reads from the previous session are cancelled rather than displayed. This is separate from provider permission errors and does not trigger a page reload.
- Agents renders server-resolved logical rows without browser-side name deduplication. Canonical and exact source links resolve to the same saved detail; every linked package retains its own inspection, access, installation and block target. Opening unified details does not require a Graph package-detail read, and an unavailable auxiliary package catalog does not hide saved Power Platform rows.
- Agent links normalize canonical/native GUID casing, case-insensitive environments and equivalent percent encoding before lookup and request ownership; opaque package/native IDs remain case-sensitive. Ambiguous source membership is left to the server, even when a source alias equals a displayed row ID. Detail and quarantine restoration share identical pending logical reads. Browser history closes or replaces obsolete details immediately, while tab-only changes retain the same saved detail and pending read.
- Published-version selection starts one saved-detail read, including versions already present in a paged group's preview. Switching versions cancels obsolete reads; late results cannot replace the chosen version. Failed reads offer **Retry saved details** even for versions outside the loaded preview, without selecting a different management target.
- Verified package mutations retain an inspected off-preview version while inventory reloads, without repeating its saved-detail read. A new inventory selection revalidates that exact version's group membership before restoring its controls, including when filters move the group off-page; it never silently substitutes the primary version.
- A pending inventory reload preserves the selected detail read and its retry state, and pauses version selection until the inventory settles. Details waiting on inventory are labelled as waiting, not loading. If inventory reload fails, an existing detail read may still finish; failed details are not retried automatically, including after unrelated management actions. Repeated in-flight saved-detail retries share the current request. A successfully replaced inventory selection reloads details against that new selection. Only the current parent-owned detail is retained, fenced by session, logical agent and saved selection; there is no separate package-ID-only detail cache.
- Agent people reuse saved checked directory identities plus a separate persistent cache for referenced creators/owners outside that snapshot. Neither membership nor absence establishes paid Copilot entitlement. Authorized detail lookups and retries update the shared cache and refresh table labels. Not-found and lookup-failed remain distinct from unresolved; none is labelled deleted. Known names remain visible after a failed lookup with their original observation time. Lists never scan the directory, and the checked Users roster is not expanded.
- Source-only person references do not manufacture directory evidence: they remain unverified IDs with explicit lookup, not navigable resolved users. Repeated lookup activations share the pending request, and retired retry handlers cannot restart it after an account or agent round trip. Equivalent saved-person property ordering and GUID casing preserve pending requests, returned names, and failures.
- Browser-local people lookup results, failures, and attempts are retired when the agent, principal, roles, or saved person evidence changes. Returning to a prior scope cannot revive them or replay a cancelled lookup. Losing directory permission cancels an active lookup while preserving already-returned names; restored permission requires an explicit lookup rather than restarting the abandoned request. Person links recheck saved or returned evidence expiry at activation, even if the display's expiry timer is delayed; expiry never starts a directory lookup.
- **Agents in catalog** (or the selected inventory scope) includes agents users cannot access. **Available to end users** counts agents with an unblocked package assigned to all or some users and no known native quarantine, regardless of host or publisher. Both summary controls open the corresponding unfiltered list; **Show agents** also separates unavailable access from unknown access. Counts, access labels, filtering and exports share the same saved-settings rule. Native creation/publication or previous usage alone never proves access. Report dates share the table toolbar when usage columns are visible.
- Agents response columns and **Used in selected report** use the shared selected report; the modal's **Users** tab defaults to the newest retained reporting period instead. All usage reads use automatic exact Agent ID / saved Graph package ID matches, preserving the full prefix and case even when display names differ. Matching follows existing saved canonical inventory membership only; it creates no source links, associations or report writes. The modal shows exact-agent report data without a manual association setup prompt. Missing data stays unavailable rather than zero, and overlapping report snapshots are never summed.

It shows saved-source progress and current source messages without empty tables or unavailable-data warnings behind it. The dialog traps focus and cannot be dismissed with Escape or a backdrop click. Navigation and deep links are preserved, and the requested dashboard opens automatically after setup completes. **View sync details** and **Review permissions** provide access to recovery pages without unlocking incomplete dashboards.

The dialog uses the server's per-account saved-success markers, not browser storage or inventory row counts. It survives reloads and reappears after saved data or the database is reset. It disappears when Users, Graph packages, and Power Platform have all synced successfully, including successful zero-record collections. CSV usage imports are a separate step and do not block first-sync completion. Established workspaces remain usable during later background syncs.

Status-read errors remain visible with **Retry status check**. Source failures show their actual messages, with **Sign in again** or **Review permissions** where applicable. Current-run activity and recovery needs are tracked independently of saved-source progress, so refreshing an already-saved source does not falsely report a waiting step. Automatic authorization, permission, and source failures show that setup needs attention even before a run exists; **Sign in again** remains available when authorization is required, including for an already-saved source in an active run. **Retry incomplete sources** preserves already-saved sources. Running or waiting runs cannot be duplicated; Sync retains run details and cancellation controls. Paused, offline, or unavailable automatic checks are reported instead of claiming that collection is running.

First-sync commands wait for pending status reads and remain disabled while status is unavailable. A command error stays visible but does not block retry after a fresh read confirms that no run is active; another status check is not required. Status retries show **Checking status...** and share the pending read. **Review permissions** uses workbench navigation, preserving session-scoped automatic-refresh pauses and sync ownership rather than reloading the application. Offline guidance takes precedence over paused-check messaging because manual sync also needs a connection.

When a known saved-data revision changes, top-level Users and reporting views retain their query and filters but load the first page of a fresh selection, clearing old rows and closing old details while it loads. They do not replay the pre-sync selection ID or cursor. Concurrent identical initial reads may share evidence. Returning to a recent Users, overview or report-selector filter can reuse its unexpired, unretired first page within the 30-second retention window; other query visits and explicit restarts capture fresh evidence. Explicitly selected child reads remain pinned to their parent evidence. Selection and report-set UUID comparisons accept case-equivalent identifiers, matching backend validation, but still reject different identifiers. Report-page requests and cache identities normalize UUID casing, so casing-only changes reuse pending and cached evidence; selection invalidation withdraws every case-equivalent page. A top-level read automatically recaptures once per query visit or explicit restart if a concurrent saved-data update invalidates its selection before the revision notification arrives; paging does not renew this attempt, and persistent invalidation still requires **Restart selection**. Authentication errors are never silently retried, and backend consistency checks remain enforced.

Open history observations and exact reported-agent details retain their independently paged reads while the parent pages within the same selection. Account changes, revisions, explicit restarts, meaningful report-query changes and parent failures retire the affected details; recovery never silently reopens them. Known report revisions also withdraw previously displayed snapshot totals. An invalidated child retires its parent selection even during parent pagination, cancelling the pending page and withdrawing rows and actions until explicit restart. Rejection also withdraws idle sibling readers of that selection, even if an earlier voluntary restart already marked their shared capture stale; readers of a newer selection remain unaffected.

Window focus, ordinary read retries and saved-query cache invalidation do not replay a rejected selection. After bounded top-level recovery is exhausted, **Restart selection** is required; pinned child reads delegate restart to their parent. This also applies when rejection reaches the cache before its observer updates the screen.

Selected agent snapshots also preserve creator-option searches/pages, pending facet reads, and admitted or ready exports while paging the same validated selection; only the agent rows wait for the next page. A report, principal/session, revision, filter, failure or invalidation boundary still withdraws that work and ignores late responses. Selection expiry remains enforced while a page is pending: obsolete reads are cancelled, top-level reads use the existing bounded recapture, and pinned child reads stop loading and require their parent's restart. Expired cached data never cancels an already-running fresh capture. Retrying a rejected facet cursor returns to the first option page with the same selection and search, without reloading the parent report.

Agent snapshot, exact-agent user, and report-facet searches use the server's case-insensitive Unicode normalization before binding requests and cursors. Equivalent edits preserve the displayed input, current pages, open details and admitted exports without another read. Empty exact-agent user pages distinguish no matching search results from an empty page of known matches or an agent with no reported users, using server counts rather than page length.

Agent snapshot empty states likewise distinguish no reported agents, no matching filters and an empty page of known matches. Missing, unselected, deleted and incomplete reports retain their specific availability labels and do not display zero-valued activity analytics. Undated agents are not labelled never used; activity-window responses and distinct users are full-snapshot totals for agents selected by their last-activity dates, not activity measured within that window.

Report provenance labels observed activity ranges and admin-supplied periods separately from source-provided reporting periods. Unknown source freshness is visible without expanding technical details, even for a recently imported report; it is independent of the report's out-of-date status. Import time and activity dates do not prove source freshness. Non-paid user activity requires both a report and current directory license verification: missing reports keep their specific availability reason, and partial, stale or unavailable license evidence shows an unavailable cohort rather than zero matches or filter-recovery advice.

Usage formatting preserves exact nonnegative integer counts, including zero; invalid or missing counts remain unknown. Dates must be valid calendar dates or unambiguous zoned timestamps and are displayed in UTC, without normalizing impossible days into reported activity. Invalid or backwards reporting ranges are unavailable. Trend charts retain such snapshots in their table but do not plot them or compare them as growth; invalid counts remain gaps rather than zero, and comparisons require chronological, complete report dates.

Report-management deletion and explicit recovery capture fresh history even before a workspace revision arrives. Their remounted readers never reuse completed or pending pre-operation peer reads. Initial history readers still share requests, and publishing the workspace revision alongside the local reload does not request history twice.

The compact report selector retires unsent previews when their history evidence fails, expires or is replaced, while unchanged focus revalidation preserves them. Already submitted selections remain observed across revision reloads until completion, unless the selector unmounts or its account/session/authority changes. Completion refreshes the current revision's options and notifies the current workspace handler, so a pre-commit revision read cannot remain cached as the selected report. Selection and recovery actions admit once before disabled controls render; selection admission and preview completion also check the authoritative cache before observer notifications render. Confirmations preserve their signed payload while comparing UUIDs case-insensitively. Metadata-only retries do not invalidate unrelated dashboards or reannounce a successful selection. Option-read and mutation access denials suspend automatic option reads, including revision reloads, until explicit **Retry** or an authority change.

Exact reported-agent reads announce loading and hide obsolete evidence during revision reloads or retries. Relationships wait for current exact evidence. Selection expiry is validated on delivery, by a local timer and on focus; expiry or a rejected relationship selection withdraws exact evidence and cancels dependent reads. Simultaneous retries share one request. A filter-only transport failure may still show explicitly labelled immutable totals for the same retained report, but never across a known revision. Retained totals expire with the selection that supplied them, even while another filter read is pending or failed; retiring those totals neither cancels nor repeats a fresh capture. Leaving a report or activity-window context discards its totals, so an abandoned A–B–A navigation cannot revive them before new evidence arrives.

Retry state belongs to the exact page-read lifecycle: a pending retry cannot hide a replacement selection or settle a newer retry. Restart retires the previous shared capture for future observers without cancelling reads still needed by mounted peers. Late responses and pinned peer revalidation cannot make that capture reusable; only a fresh capture started after retirement restores its short-lived cache eligibility.

Repeated or simultaneous **Retry saved data** actions share the current request rather than cancelling it and issuing duplicates. Export rejection differs from a voluntary restart: only the rejected selection's page reads are cancelled, and its cached evidence cannot become reusable when a late response arrives.

Report retries check selection expiry at admission, even before the expiry timer updates the screen. Cache invalidation cannot replay locally expired pinned evidence either. Expiry supersedes a previous page failure: top-level reads use their bounded recovery, and pinned reads require their parent's restart. Access denials suspend automatic reads, including cache invalidation, until explicit retry or an owner change; expiry never silently retries denied access. A recovered page ignores retry handlers retained from its old failure.

Reviewed report-link paging admits only one direction per committed page and checks the current summary, history and link cache before navigation. In-flight revalidation, failures and retired account/report/page handlers cannot move its cursor or cancel a current read. Empty user and relationship pages with known matches are labelled as empty pages, not as missing report data or failed searches.
