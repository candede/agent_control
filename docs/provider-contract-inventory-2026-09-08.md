# Provider requirements

This reference summarizes the Microsoft permissions and service requirements
used by Agent Control. Provider availability and authorization are verified when
an operation runs.

The [capability registry](../backend/src/services/capabilityRegistry.ts) is the
complete, current capability-ID and Microsoft source-reference inventory. The
table below summarizes its required permissions, not a dated readiness result.

The selected package read contract is GET on `https://graph.microsoft.com/v1.0/copilot/admin/catalog/packages` with exactly `$filter=supportedHosts/any(h:h eq 'Copilot')`, or GET on that path plus one encoded, exact opaque package ID for detail. No caller-supplied origin, query, selection, expansion or headers are admitted; `$top` is not requested. Traversed continuation links may add only one nonempty `$skiptoken`, retaining the endpoint/filter, and redirects fail closed. Equivalent-link loops, duplicate exact identities, unsupported declared resource types and malformed security fields reject collection rather than publishing partial/empty success. Access principals must have a user/group type (case-insensitive validation, no aliases) and a nonblank, bounded identity without C0/C1 controls; observations preserve both strings exactly, without imposing a GUID/version format on provider IDs. Automatic due-detail refreshes retain their initiating session and delegated-read capability generation through claiming work, admission, collection and publication. Existing finite page/row/response-byte/execution limits remain enforced, and catalog refresh does not fan out detail requests. Package reads require `CopilotPackages.Read.All` or the accepted `CopilotPackages.ReadWrite.All` grant; delegated beta mutations remain one-shot with their existing permission and readback contract. These are code/mock guarantees, not live-provider qualification.

Package transport tracks settled responses before abort-race delivery. Undelivered bodies are disposed without waiting for cleanup or exposing cleanup failures. Caller cancellation and initiating authority remain authoritative; a local phase deadline retains already-observed Graph denial/throttle status, request ID and Retry-After metadata. One elapsed-time-checked logical budget includes preparation, admission, retries, response bodies and progress; extended throttling requires a cancellation signal and absolute caller execution deadline, fenced by the persisted generation deadline. An observed HTTP denial cannot be retried merely because its provider code resembles a local transport error. Valid but unrepresentable positive Retry-After delays fail closed. HTTP 429 headers establish shared cooldown/pacing independently of a stalled body or expiring caller; token-service throttling never changes that Graph-wide state.

Paced admission remains held through token renewal, durable preparation, final authority checking and physical dispatch. The next interval starts at actual dispatch, not an earlier reservation, so an elapsed-clock stall cannot collapse adjacent dispatches into a burst. Response/body waits remain concurrent; cancellation releases admission without leaving unobserved request failures.

Shared JSON/text reads count response-body bytes, preserve the UTF-8 BOM, and reject malformed UTF-8 rather than replacement-decoding identities. Consumed chunks are copied before the next read; buffered storage grows with the byte budget, not the number of small or empty chunks, and only the active read retains an abort rejection. Cancellation remains authoritative through cleanup and parse checkpoints; cleanup is nonblocking and releases only the acquired reader. Syntax failures become sanitized provider-schema errors, while local checkpoint and non-syntax parser failures retain their identity.

Repeated contract members (including escaped key spellings) also reject directory principals, typed agent identities, license catalogs/users and nested service-plan evidence, quarantine status/timestamps, Audit Search queries/records/native metadata/message references, and hunting schema/projected rows before successful admission or publication. Type-specific Resource Query contexts and unknown authoring-property omission are unchanged. Ambiguous optional Graph/quarantine error-body codes are discarded without losing the HTTP status, headers or header-established throttling; they cannot fabricate a permission, rollout or dependency-throttle classification. These guarantees are service-free fixture checks, not live-provider qualification.

Package mutation items retain one absolute 90-second execution deadline through control settlement/preflight, final authorization, the dispatch marker, one-shot write, convergence and publication; GET-only reconciliation uses one 30-second deadline per item. These deadlines are checked independently of delayed abort delivery. Settlement authorization and each local control/canonical publication retain the initiating session, capability and provider admission assertion, synchronously rechecked before COMMIT and immediately after settlement. Mutation transport and convergence waits honor the shorter caller deadline, and rejected access-preflight/write or convergence-wait work rechecks initiating authority before returning its failure. Expiry before the dispatch marker fails unsent work; expiry after it remains inconclusive, never a successful write or an automatically replayable mutation.

Provider-derived access principal IDs remain exact, case-sensitive opaque strings through additive unions, preserved PATCH collections, frozen-state hashing and readback/reconciliation. Only user/group type casing is canonicalized for identity comparison. The frontend picker removes and filters exact identities rather than trimming or folding IDs. Direct access PATCH accepts exactly both documented own data collections, each with at most 5000 valid principals, and serializes a fresh allowlisted projection of their own resource IDs/types; input serialization hooks and extra principal members cannot alter the dispatched body. Additive unions apply the bound after exact-identity deduplication, preserving no-ops at that bound. Newly selected directory principals still require the existing Entra-object-ID validation. Previously frozen intents whose hashes depended on lossy provider-ID normalization may fail the current-prestate check; refresh and explicitly reconfirm instead of replaying them.

An access change must also be able to preserve the untouched setting through that collection-only payload: `none` with an empty collection or `some` with a nonempty collection, including known aliases and missing-scope inference from present principals. Untouched all-users access, inactive principals under `none`, or an empty collection under `some` cannot be represented without changing that setting. Preview and dispatch reject these writes as `unpreservable_access_scope` before the dispatch marker; the single-package editor explains the restriction while leaving block/unblock and the other access target available. Exact no-ops do not dispatch and remain admissible. Scope/hash/equality semantics are unchanged, so GET-only reconciliation of historical sent jobs still classifies the exact observed state without replaying their writes. Both directions of optional access canaries must preserve a representable untouched setting.

Frozen mutation states require an own data discriminator, explicit own block boolean or canonical access scopes, and dense typed own principal collections. State capture, hashing and access-intent validation never inherit evidence or execute accessors. Valid states retain their existing hash serialization, including exact opaque IDs and JSONB-independent key ordering. Access projection and direct dispatch reject unsupported target/mode/scope combinations; durable execution also requires the selected target to match the audited action. Preview, dispatch and both canary directions reject complete pre/poststates above the 65,536-byte durable JSONB-text limit, accounting for JSONB punctuation and additive union growth. GET-only reconciliation checks the saved prestate against its frozen hash but does not impose write-preservation admission on historical sent intents. Oversized divergent readback leaves a durable inconclusive outcome without truncating or persisting its optional state diagnostic; an oversized current reconciliation state cannot publish a verified receipt.

**Permissions > Check status** performs bounded readiness checks. It does not:

- import inventory;
- run audit or hunting jobs;
- make provider changes;
- grant consent;
- assign Microsoft roles;
- prove that a provider contains matching data.

The submitted operation reacquires authorization and the provider makes the
final access decision.

## Delegated and application access

Delegated access acts as the signed-in user and remains limited by that user's
roles, licenses, and service scope.

Application access must be enabled separately by an Agent Control Admin and
limited to an approved tenant-wide scope. It is not a fallback for failed
delegated access.

- `documented` means the cited Microsoft source described the operation or permission on the inventory date.
- The 2026-09-16 unified-agent review distinguishes source-metadata associations from documented Microsoft identity guarantees. The public [package element schema](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/api/admin-settings/package/resources/packageelement) defines `definition` as a complete JSON string, but does not type the observed `AgentMetadatas.SourceIds` inner schema. A local canonical UUID identifies the application's resolved row, not a new Microsoft identity or permission grant.
- Studio links use explicit environment and typed native identities against the [Power Platform identity fields](https://learn.microsoft.com/en-us/microsoft-copilot-studio/admin-agent-inventory). When optional typed bot fields are omitted, exact environment + schema-name + native-GUID agreement with package `SourceIds.EnvironmentId`, `SchemaName`, and `CdsBotId` provides corroborated evidence. This is not a universal native-ID/CDS-ID alias. Opaque package `AgentIdentityId` and Power Platform `entraAgentId` are retained as source-specific observations: a difference does not overturn agreeing native identities. A missing control bot field is qualified only from the explicit package CDS ID with full corroboration and fresh (<24-hour), same-principal/current observations; server target resolution repeats that proof.
- Agent Builder/declarative packages can omit `AgentMetadatas`. A unique authorized resource whose native ID **and GUID schema name** both equal a declared package `manifestId` provides a source-observed manifest association. This pattern was checked across the complete local saved inventory, but the [agent inventory schema](https://learn.microsoft.com/en-us/microsoft-copilot-studio/admin-agent-inventory#core-properties) does not promise a universal Builder/manifest foreign key. The association requires declarative kind plus the full identity agreement, never a name or an inferred host. It never supplies a CDS quarantine ID.
- [Manifest `bots[].botId`](https://learn.microsoft.com/en-us/microsoft-365/extensibility/schema/root-bots?view=m365-app-1.30#botid) is a bot **application** ID. [Custom-engine `id`](https://learn.microsoft.com/en-us/microsoft-365/extensibility/schema/root-copilot-agents-custom-engine-agents?view=m365-app-1.30#id) must refer to that bot ID when `type` is `bot`; the extra returned `botId` member is optional corroborating service metadata, not a required public manifest field. Package representations can share a uniquely anchored native association through this same bot application, retaining the related package IDs as provenance. Competing native/environment anchors remain ambiguous. This is a correlation within the authorized saved inventory, not a Microsoft-guaranteed one-to-one relation. An alias package never provides or renews the anchor's native-control proof.
- Custom-engine correlation also preserves independently declared declarative manifest claims. Distinct manifests or disagreement with a native ID/GUID schema prevent alias association, even when the competing agent is absent from saved Power Platform inventory. A unique compatible manifest keeps its environment-scoped source-only grouping; sharing a bot application never substitutes a CDS control ID.
- Control qualification requires the exact package ID's own catalog observation and its identity observation to be fresh. Freshness compares complete validated timestamp instants, including supported sub-millisecond fractions and timezone offsets; malformed, future and expired observations cannot qualify controls.
- Sparse control readbacks preserve omitted identity evidence, but positive changes to opaque catalog `appId`, `assetId`, `version`, or `manifestVersion` markers compare exactly, even for GUID-shaped strings. Typed manifest/native GUIDs remain case-insensitive. A detected conflict survives persistence and catalog/detail enrichment, withdraws matching facts and native-control qualification, and requires a new exact identity read.
- Repeated contract-bearing members in Graph package response JSON are rejected before admission, including escaped spellings of the same member: package identity, summaries, revision/security fields, access collections/principals, element groups/elements, and catalog value/count/continuation evidence must never use last-value-wins parsing. Repeated identity properties within an element definition are also invalid evidence. Graph rejects duplicate AgentMetadatas identity fields during admission; saved native/custom-engine linking and identity-only exports also reject duplicate identity fields rather than choosing the last value. Repeated unrelated authoring properties and compatible metadata fragments in separate elements remain supported.
- Identity evidence must come from own data properties, not inherited fields or accessors. Admission includes non-enumerable own members so explicit security/revision evidence cannot silently become omitted, and rejects non-enumerable accessors without invoking them. Saved identity readers enforce the same 50-group, 100-elements-per-group and 2,048,000-byte observation bounds as admission; native metadata is additionally limited to 16 fragments and a 16,384-byte identity-field projection. Unrelated authoring JSON remains intact within the observation budget. Custom-engine evidence lists only elements corroborating the selected bot application. Control qualification requires own timestamps on both the catalog and any separately supplied identity observation, retaining exact fractional-instant comparisons.
- Names, application registrations, blueprint IDs, and equal GUIDs of unrelated kinds alone never merge agents. GUID casing is normalized without stripping the `Default-` environment prefix or folding opaque package identifiers. Canonical source membership is tenant/account-private and bound to current observations; authorized-query collection verification remains distinct from identity matching and provider authorization.
- The 2026-09-17 verification repair uses the [Query Resources result contract](https://learn.microsoft.com/en-us/rest/api/power-platform/resourcequery/resource-query/query-resources): provider total, completed pagination, exact executed types/environment, unique source identities, and actual saved rows must agree. The current schema persists actual queried types rather than coverage inferred from optional ID-token `wids`. Missing role hints are neither denial evidence nor a reason to label a complete query partial. All [documented supported inventory roles](https://learn.microsoft.com/en-us/power-platform/admin/power-platform-inventory) include agents; the API does not return an independent tenant-authorization attestation. Verification is explicitly scoped to authorized saved queries, with [classic/V1 exclusions and indexing delay](https://learn.microsoft.com/en-us/microsoft-copilot-studio/admin-agent-inventory) preserved. It does not claim every possible tenant agent or renew live-operation authorization.
- Missing live evidence is reported separately from exact registry decisions such as `not_configured`, `missing_internal_role`, `preview_disabled`, or `unknown`. Interpret `available` together with `verification`: only `provider` denotes a successful current provider check or operation; `token`, `on_demand`, and `local` do not establish provider-operation access.
- A permission listing does not prove tenant consent, licensing, role assignment, national-cloud support, API stability, or successful access to tenant data.
- Microsoft access tokens are an opaque client contract. Runtime evidence uses validated MSAL response metadata and returned delegated scopes or safely exposed application roles; readable token claims can reject contradictions but are not required for a valid provider response.
- Evidence is principal-, resource-, mode-, permission-, contract-, configuration-, and environment-specific. It expires after five minutes, immediately becomes unauthorized, and remains stale diagnostic history only until explicit operator retention.

- Resource Query rejects repeated contract-bearing JSON members, including escaped spellings of the same member, before access-check evidence, page progress or saved publication: totals, counts, continuation, resource identities/properties and projected connector operations cannot use last-value-wins parsing. Property contexts follow the exact resource type regardless of member order: duplicate agent-only properties within an environment remain unknown and are omitted, including their nested connector/count data. Repeated type discriminators are still rejected. Unknown authoring properties remain omitted. Response bytes, page/row limits, cancellation and exact completed-enumeration checks still apply. The shared scanner's depth bound includes the deepest contract container; it is not a global depth limit on omitted authoring JSON.
- Resource Query enumeration rejects a tokenless terminal page whose cumulative count does not equal the provider total before staging that page or recording its progress. The bounded access check remains a sample, not an enumeration. After a consumer's page write settles, cancellation and synchronous authority are checked before progress callbacks; in-flight writes and callbacks still settle before refresh cleanup.
- Resource Query reacquires the scoped delegated token before each provider dispatch, including retries of the same page after throttling or transport/body failures. Cancellation and initiating authority also own rejected token, retry and progress callbacks; cancellation stops the underlying retry timer rather than only abandoning its promise. Valid `Retry-After` delays are never shortened: a delay exceeding the bounded retry ceiling ends the read without an early retry. Terminal HTTP failures preserve sanitized request correlation and provider cooldown metadata so readiness checks retain the actual cooldown rather than the default backoff.
- Power Platform refresh submission rejects environment scopes containing NUL, line breaks or lone Unicode surrogates before database admission. Valid supplementary Unicode and opaque casing remain exact, so persisted scope and idempotency evidence do not disagree with query validation.
- Power Platform refresh submission pins session/capability authority and provider admissions through its final transaction write. Private job reads/history and requested cancellation reject delayed responses after session revocation or replacement; internal sync cleanup still stops owned work after revocation. If retention expires between admission/cancellation and the status read, the API returns `inventory_job_expired`, never an empty success response.
- The Power Platform job's persisted 30-minute deadline includes authorization waiting; resume does not renew it. Retained expired waiting/running jobs are reported as failed (`inventory_job_expired`), do not consume unfinished-job quota, and require an explicit new refresh. Resumed progress starts at zero. Cancellation and execution expiry interrupt pending provider authorization without waiting for its late result; pending admission/publication writes still settle before drain completes. Non-authorization admission failures are saved as failed jobs, not sign-in waits. Explicit refresh/resume rechecks failed readiness while preserving provider throttling cooldowns. Viewer/Admin application-role failures are distinct from Microsoft consent/provider-role failures; the inspector links permission failures to Permissions. COMMIT is the success boundary: later stream/observer cleanup failures cannot relabel publication or prevent reconciliation from being requested.
- Inventory generations notify source workers immediately after an acknowledged `COMMIT`, before measurement callbacks or client release. Both Power Platform and Graph package workers retain durable success when later cleanup fails, while still logging the cleanup failure; a rejected COMMIT or server rollback is never a success notification.
- Power Platform startup recovery completes all bounded orphan/expiry batches without dispatching provider work and rechecks operational admissions between batches; maintenance stops further recovery.
