# Provider contract inventory

Inventory date: 2026-09-08; package operation pages, official usage-report, Purview Audit Search and Defender/Agent 365 hunting sources rechecked 2026-09-09

This inventory records the source contract implemented by `backend/src/services/capabilityRegistry.ts`. Documentation availability, token-only checks and `on_demand` authorization are not live provider-operation evidence. Remote operations require capability-specific credentials, grants, provider roles, licensing, and supported endpoint behavior. Automatic delegated checks cover the package catalog, Graph directory, Power Platform inventory, quarantine read, Purview Audit Search, Defender hunting and implemented Admin package access/block and quarantine management. Admin writes initially report `on_demand` authorization with no prior evidence; non-mutating token checks replace that with expiring token evidence or an actionable failure. Provider credentials are checked again when an operation is submitted, without prior canary evidence. Each safe provider check separately bounds token acquisition to ten seconds and provider reads to ten seconds, except the first-page catalog read receives thirty seconds including bounded body consumption. The set runs concurrently, automatically reuses fresh successes or failures during the five-minute evidence TTL/cooldown, and coalesces equivalent batch and evidence-key work. Explicit Check status uses `?retry=failed` to retry eligible failed delegated checks while retaining successes and active throttling cooldowns.

Permission checks never start application/shared provider work, imports, mutations, canaries, audit/hunting workloads or refresh jobs. Separately, opening Agents with no broad saved snapshot starts one initial delegated read-only inventory refresh per authorized session; a first-page catalog check alone is not an inventory import, and subsequent Refresh/retry is explicit. Disabled optional application modes are inactive/unconfigured rather than delegated failures and never replace delegated mode. Once explicitly enabled they participate normally; missing shared-scope approval is then degraded/not-configured rather than excluded. Unknown, unprobed and checking are not failures. Actual unavailable providers must fail explicitly and must not return synthetic data.

## Evidence interpretation

- `documented` means the cited Microsoft source described the operation or permission on the inventory date.
- Missing live evidence is reported separately from exact registry decisions such as `not_configured`, `missing_internal_role`, `preview_disabled`, or `unknown`. Only a current successful provider probe can establish `available` for a delivered read adapter.
- A permission listing does not prove tenant consent, licensing, role assignment, national-cloud support, API stability, or successful access to tenant data.
- Microsoft access tokens are an opaque client contract. Runtime evidence uses validated MSAL response metadata and returned delegated scopes or safely exposed application roles; readable token claims can reject contradictions but are not required for a valid provider response.
- Evidence is principal-, resource-, mode-, permission-, contract-, configuration-, and environment-specific. It expires after five minutes, immediately becomes unauthorized, and remains stale diagnostic history only until explicit operator retention.
- Preview/beta contracts can change without compatibility guarantees. Record dated contract reviews and disclose preview/concurrency risks; review records are not ordinary-write activation switches.
- Optional package write qualification follows [the reversible canary protocol](mutation-canaries.md). Phase 05 performed no live provider write; this remains a live-evidence gap, not a gate on ordinary Admin-confirmed access/block operations. Owner reassignment has no implemented product workflow or documented owner readback. Saved reads remain independently usable.
- Purview Audit Search selects `POST /v1.0/security/auditLog/queries` with singular `serviceFilter`, a required subset of code-owned preset operations, direct create/get objects, and collection envelopes for query/record lists. Microsoft's resource page still says plural `serviceFilters`, while single-query GET still lists `ThreatIntelligence.Read.All`. GET response prose describes a direct object but its example wraps an object in `value` and includes `keywordFilter`; that example shape is rejected. Agent Control neither sends fallback shapes nor requests the unrelated permission. A delegated explicit bounded search directly performs and evidences create, poll and records for its principal; automatic checks acquire a token only and create no query. Application/shared mode retains separate Admin approval and qualification. No live query ran in Phase 07.
- Purview projection version 1 treats the Graph `auditLogRecord` as an outer wrapper and the native Office audit object as a separate schema. Graph documents wrapper `userType` as a string enum, but Office documents native `UserType` as `Edm.Int32` values 0-10; the native value is validated but not exposed. Office record types `256` and `261` identify `PowerPlatformAdministratorActivity` and `CopilotInteraction`. Copilot metadata is read only below `CopilotEventData`; message metadata follows the newer emitted JSON casing `Messages[].ID` and `Messages[].isPrompt`. The Graph `defaultAuditData` page defines no native child properties, and the older Copilot schema uses conflicting message casing, so no aliases or undocumented fields are projected. [Graph wrapper](https://learn.microsoft.com/en-us/graph/api/resources/security-auditlogrecord?view=graph-rest-1.0), [default audit data](https://learn.microsoft.com/en-us/graph/api/resources/security-defaultauditdata?view=graph-rest-1.0), [Office common schema](https://learn.microsoft.com/en-us/office/office-365-management-api/office-365-management-activity-api-schema), [Copilot schema](https://learn.microsoft.com/en-us/office/office-365-management-api/copilot-schema), [emitted Copilot example](https://learn.microsoft.com/en-us/purview/audit-copilot).
- Defender hunting uses only `POST /v1.0/security/runHuntingQuery` with exact `Query` and `Timespan` body keys. The application accepts no `workspaceId`; Graph-selected primary-workspace fallback therefore cannot be presented as requested-workspace isolation. Code-owned `AgentsInfo` and Agent 365 `CloudAppEvents` projections are capped at 200 retained rows and 2 MB. `AgentsInfo` remains preview. Delegated consent remains subject to Defender RBAC/data-source assignment, and empty success cannot identify a missing license, connector, table or rollout. Original dynamic objects, raw events, messages, instructions, memory and tool content are discarded.
